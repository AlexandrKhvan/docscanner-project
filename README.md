# DocScanner

Локальный сканер документов на Python, OpenCV и FastAPI. Находит границы листа
на фотографии, исправляет перспективу и сохраняет результат как изображение или PDF.
Файлы обрабатываются на вашем компьютере, без внешних сервисов.

## Возможности

- Автоматическое выравнивание: Canny + HED, запасной поиск бумаги через k-means.
- Цветной, серый и чёрно-белый режимы, повышение читаемости текста.
- Автоматическая обрезка полей с настройками и пресетами.
- Один файл → PNG, JPG или PDF; несколько файлов → многостраничный PDF или ZIP.
- Веб-интерфейс с миниатюрами и ручным редактором:
  обрезка, четыре угла, поворот и кисть. Правки сохраняются для каждой страницы отдельно.
- Учёт ориентации фото из EXIF; прозрачные участки становятся белыми.

## Запуск из корня репозитория

Нужен Python 3.10+. Команды выполняются из папки docscanner-project, где лежит этот README.

### Windows / PowerShell

~~~powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn docscan.api.main:app --reload --port 8000
~~~

Активация окружения не обязательна. Если используете существующую папку venv,
замените .venv на venv в командах.

### Linux / macOS

~~~bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m uvicorn docscan.api.main:app --reload --port 8000
~~~

Откройте [сканер](http://localhost:8000) или [документацию API](http://localhost:8000/docs).

## Использование

1. Выберите или перетащите изображения в область загрузки.
2. Выберите режим, длинную сторону результата и настройки обрезки.
3. Нажмите «Посмотреть и поправить автообрезку»: проверьте рамку на исходном фото,
   при необходимости передвиньте границы и нажмите «Применить».
4. Запустите сканирование одного файла или создайте PDF/ZIP из всего пакета.
5. Скачайте результат по появившейся кнопке.

Вход — изображения, например JPEG, PNG, WebP, BMP или TIFF. Импорт PDF и HEIC
не реализован. Ограничения: **20 МБ и 40 мегапикселей на изображение,
не более 20 файлов в пакете**. Из многостраничного TIFF берётся первая страница.

Если в пакете есть повреждённое изображение, API вернёт ошибку с его именем,
чтобы страницы не исчезали молча. Порядок страниц соответствует порядку загрузки.
Одинаковые имена в ZIP получают числовые суффиксы.

## Ручной редактор

Откройте миниатюру или кнопку «Редактировать». По умолчанию сохраняется весь кадр.
Кнопка **«Посмотреть и поправить автообрезку»** сначала предлагает автоматические границы.
В этом режиме при переходе к новой странице её границы тоже подбираются автоматически;
уже отредактированные черновики сохраняются.

В редакторе справа показан **результат обрезки** с выбранным режимом и чёткостью текста.
Он обновляется после изменения рамки, углов, поворота или кисти. Ссылка «Открыть в полном
размере» позволяет проверить мелкие буквы. Предпросмотр строится из исходного изображения:
до применения обрезки можно вернуть поля, раздвинув рамку или нажав **«Больше полей»**.
«Найти границы автоматически» повторяет поиск с текущими настройками align/trim.

Ползунок **«Чёткость текста»** регулирует локальный контраст и резкость букв: 0% отключает
усиление, 50% — умеренное значение по умолчанию, 100% — максимальное. Он работает в цветном,
сером и ч/б режимах, включая пакетный PDF/ZIP. Режим и чёткость в редакторе синхронизированы
с главными настройками и применяются при сканировании; в сохранённую геометрию они не запекаются.
Это обработка изображения, без OCR и восстановления отсутствующих деталей.

Автоматический trim по умолчанию оставляет запас 12 px, не срезает внутренний отступ
и отказывается от среза более 12% ширины или высоты; это ограничение относится к trim,
а не к исправлению перспективы по найденному контуру листа.

- **Обрезка** — перемещайте рамку и её края. Можно задать A4, квадрат и другие пропорции.
- **Четыре угла** — поставьте точки на углы листа; при применении OpenCV выпрямит перспективу.
  Это альтернатива прямоугольной обрезке; скрытая рамка дополнительно не применяется.
- **Поворот** — шаги 90° и 1°, без чёрных полей. Выделение пересчитывается вместе с фото.
- **Кисть** — закрашивает участки белым. ПКМ или Alt + перетаскивание стирает маску;
  диаметр указан в пикселях фото и не меняется от масштаба окна.
- Колёсико меняет масштаб; **Пробел + перетаскивание** или инструмент «Перемещение» двигает вид.
  Масштаб и размер окна не меняют выбранную область в итоговом файле.

Черновики сохраняются отдельно для каждой страницы при переходах и закрытии редактора.
Они хранятся в памяти вкладки: перезагрузка страницы или новая загрузка файлов их сбрасывает.
Нажмите **«Применить»**, чтобы сохранить изменения в миниатюру и включить их в PDF/ZIP.
После применения можно продолжить редактирование уже полученного результата.
При ошибке запроса черновик остаётся доступен; Esc отменяет ожидание обработки и закрывает окно.

«Убрать выделение» отменяет только обрезку/четыре угла, сохраняя поворот и кисть.
«Вернуть исходное фото» сбрасывает все правки выбранной страницы, включая применённые.
При сканировании страниц с применёнными правками автоматические align/trim отключаются,
а режим цвета и выбранный размер результата продолжают действовать.

Применение работает через локальный API. Результат сохраняется в PNG; если он превышает
20 МБ, используется JPEG с качеством 95, чтобы файл можно было обработать повторно.

## API

Один файл:

~~~bash
curl -X POST "http://localhost:8000/scan?mode=bw&fmt=png&long_side=2400" -F "file=@photo.jpg" --output scan.png
~~~

Пакет:

~~~bash
curl -X POST "http://localhost:8000/scan/batch?mode=gray&out=pdf" -F "files=@page1.jpg" -F "files=@page2.jpg" --output scans.pdf
~~~

В PowerShell используйте curl.exe. Для ZIP задайте out=zip&img_fmt=png или out=zip&img_fmt=jpg.
Для пакета с ручными правками передайте повторяющийся параметр preserve с индексами
страниц от нуля, например preserve=0&preserve=2. Только эти страницы пропустят align/trim.

Редактор отправляет POST /edit как multipart/form-data: file — исходное изображение,
settings — JSON вида {"rotation":90,"crop":[30,40,100,80]}, mask — необязательная
PNG-маска с альфа-каналом в размерах исходного фото. rotation задан по часовой стрелке.
crop содержит x, y, ширину и высоту в координатах повёрнутого изображения.
Вместо crop можно передать quad: четыре пары [x,y] по часовой стрелке, начиная с верхнего
левого угла. Обрезку и quad одновременно передавать нельзя. Маска применяется до поворота.

POST /detect принимает file и настройки align/trim/rotation в query и возвращает предложенные
границы quad, прямоугольник crop и признаки found/trimmed. Изображение не обрезается.
POST /preview принимает те же file/settings/mask, что /edit, плюс mode/long_side/text_strength
в query; возвращает PNG с выбранной геометрией и обработкой текста без сохранения правок.
После применения геометрии через /edit и сканирования с align=false&trim=false предпросмотр
соответствует итоговому PNG с теми же параметрами обработки.

| Параметр | Значения | По умолчанию |
| --- | --- | --- |
| mode | bw, gray, color | bw |
| long_side | 600–6000 px; длинная сторона итогового изображения | 2400 |
| text_strength | 0–1; контраст и резкость текста, 0 отключает усиление | 0.5 |
| fmt | png, jpg, pdf; для /scan | png |
| out | pdf, zip; для /scan/batch | pdf |
| img_fmt | png, jpg; изображения внутри ZIP | jpg |
| align | true, false; автоматическое выравнивание | true |
| trim | true, false; автоматическая обрезка полей | true |
| trim_margin | 0–40 px; внутренний отступ | 0 |
| trim_thr | 0.05–0.6; порог определения границы | 0.22 |
| trim_sustain | 3–50; устойчивость определения границы | 6 |
| trim_pad | 0–40 px; внешний отступ | 12 |

PDF собирается с разрешением 300 dpi. Ч/б и серые страницы сохраняются без JPEG-сжатия,
цветные — с JPEG-сжатием. Это PDF из изображений, без распознанного текстового слоя.

## Проверки

~~~powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q
~~~

Проверки геометрии и действий редактора (Node.js 20+, без дополнительных пакетов):

~~~powershell
node --test tests/editor-geometry.test.cjs tests/editor-session.test.cjs
~~~

Тесты проверяют API, форматы выгрузки, пакетную обработку, ошибки загрузки,
ориентацию EXIF, прозрачность, геометрию и размер результата.
Изображения создаются в памяти; фотографии документов не нужны.
Проверка HED использует приложенную модель; если её нет, этот тест пропускается.

## Структура

~~~text
docscan/
  api/main.py           # FastAPI и экспорт файлов
  src/pipeline.py       # поиск документа и обработка
  src/geometry.py       # порядок углов и преобразование перспективы
  src/editing.py        # ручные повороты, обрезка, перспектива и маска
  src/hed.py            # OpenCV DNN / HED
  models/hed/           # конфигурация и веса HED
  web/index.html        # интерфейс и ручной редактор
  web/editor.js         # состояние редактора и обработка действий
  web/editor-geometry.js # координаты изображения и окна предпросмотра
tests/                  # проверки API и обработки
~~~

HED работает на CPU. Если модели отсутствуют или не загружаются,
сканер использует обычный поиск контуров и k-means.
Подготовка входа соответствует [примеру авторов HED](https://github.com/s9xie/hed/blob/master/examples/hed/HED-tutorial.ipynb).

## Что ещё требует доработки

- Поиск границ может ошибаться на светлом фоне, сильных тенях и документах,
  которые выходят за кадр. Автоматическое выравнивание и обрезку можно отключить.
- OCR, импорт PDF/HEIC, перестановка страниц и сохранение проектов пока не реализованы.
